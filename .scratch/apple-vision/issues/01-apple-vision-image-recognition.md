# 01: Локальное распознавание изображений через Apple Vision

Status: implemented-awaiting-ci-verification

**What to build:** Пользователь явно выбирает `apple-vision` через OCR CLI или публичный Python API и получает локально распознанный текст, уверенность и координаты в существующем формате результатов. Общий инструмент заменяет необходимость отдельного Swift-хелпера.

**Blocked by:** None (can start immediately).

## Acceptance criteria

- [x] `apple-vision` доступен через CLI и публичный интерфейс распознавания библиотеки.
- [x] Доступ к системному Apple Vision реализован через PyObjC как необязательную зависимость extra `apple-vision`, без компиляции Swift-хелпера и отдельного кэша бинарников.
- [x] Используется режим `.accurate`; быстрый режим не добавлен.
- [x] Параметры языков согласованы с существующим интерфейсом; неподдерживаемые настройки обрабатываются явно.
- [x] Результат содержит текст, уверенность 0–100 и пиксельные прямоугольники в принятой системе координат. Координаты строки не выдаются за точные координаты отдельных слов.
- [x] Проверка требований побочно-безопасна: не импортирует движок, не выполняет OCR, сетевых запросов или загрузки моделей.
- [x] Неподдерживаемая платформа, отсутствующие зависимости и ошибка их импорта дают структурированные ошибки в существующем формате.
- [x] При недоступности явно выбранного движка нет скрытого переключения на другой движок или облачный API.
- [x] Дефолт `tesseract`, значение API-движка `vision` и поведение существующих движков сохранены.
- [x] Автоматические тесты проверяют внешний контракт распознавания, ошибки и преобразование геометрии, а не внутреннее устройство адаптера.
- [ ] Отдельная macOS-задача CI выполняет реальный smoke-тест на синтетическом изображении: проверяет существенные строки, уверенность и границы координат. Существующий Ubuntu CI сохранён.

## Comments

### 2026-11-15 — Реализация и проверка

- Добавлены extra `apple-vision`, локальный адаптер PyObjC, структурированные проверки платформы/модулей, CLI и отдельная задача `apple-vision-smoke` (`macos-14`, Python 3.12). Ubuntu CI не изменён.
- Публичные тесты используют подмену внешней границы PyObjC, а не внутренних функций адаптера. Проверены текст, уверенность, перевод координат из нижнего левого угла в верхний левый и масштабирование. Элементы `words` содержат целые наблюдения с `granularity: line`.
- `lang=auto` использует системное определение языка (macOS 13+); составные коды `rus+eng` и основные коды Tesseract преобразуются в идентификаторы Vision. Языки проверяются по поддержке текущей версии запроса. Неподдерживаемый язык или нестандартный `psm` дают явную ошибку.
- Зафиксированы RED → GREEN: неизвестный движок в probe, пропущенные зависимости, неподдерживаемый движок в `recognize`, CLI choice, нестандартный `psm`, RuntimeError при импорте, код `fra`, игнорирование `psm` при cache hit. На каждом шаге запускались узкие тесты.
- Итоговый полный прогон: `228 passed, 1 skipped, 10 subtests passed` (Python 3.14.3). Пропущен только opt-in smoke. `compileall` и `git diff --check` прошли.
- Реальный запуск `OCR_APPLE_VISION_SMOKE=1 .venv/bin/python -m pytest tests/test_apple_vision_smoke.py -q -p no:tmpdir` **заблокирован**: структурированная ошибка `missing_apple_vision_packages` для Vision/Foundation/Quartz/objc. Пакеты не устанавливались; установленный CLI не менялся. Задача CI добавлена, но ещё не выполнялась.
- `uv lock --offline` не смог разрешить зависимости: в кэше отсутствует metadata `camelot-py`. `uv.lock` оставлен без изменений; обновление lock и установка extra требуют отдельного согласованного этапа.
- Context7 вызван через `npx --no-install ctx7 ...`, но CLI отсутствует; MCP Context7 не настроен. Установка не выполнялась. API сверены напрямую с документацией Apple и upstream-тестами PyObjC: `test_vnrecognizetextrequest.py`, `test_vnrequesthandler.py`, описание `VNDetectedObjectObservation.boundingBox`. Проверка через Context7 остаётся незавершённой.
- Тикет не отмечен завершённым до реального smoke и проверки зависимостей/lock. Личные материалы не читались и никуда не отправлялись.

### 2026-11-15 — Системная проверка после разрешённой установки

- Установка зависимостей и обновление CLI согласованы пользователем. Основной агент выполнил `uv sync --extra dev --extra apple-vision`, обновил `uv.lock`.
- Реальный smoke сначала воспроизвёл `NSInvalidArgumentException: key does not exist` при передаче Python `{}` в `VNImageRequestHandler`. Изолированная диагностика с тем же CGImage: Python dict — ошибка; нативный `NSDictionary.dictionary()` и nil — успешная инициализация. Адаптер теперь передаёт нативный NSDictionary; это проверенный RED → GREEN, а не предположение.
- Реальный smoke прошёл для `lang=eng+rus` и `lang=auto`, включая известные русские/английские строки, уверенность, границы и взаимное расположение координат. Добавлен успешный smoke двухстраничного растрового PDF.
- Проверенная локальная конфигурация: macOS 27.2, arm64, Python 3.14.3, PyObjC 13.0. Поддержка всей матрицы macOS/Python не заявляется.
- Первый успешный синтетический прогон занял 53.922 с; предшествующий был остановлен по лимиту 30 с. Повторная проверка: изображение с явными языками — 0.476 с, auto — 0.125 с, PDF — 0.439 с. Причины разницы не установлены.
- Публичный API и установленный CLI реально проверены на двух согласованных локальных фото; уверенность и геометрия валидны, существенные подписи проверялись по содержимому. На одном фото совпали 3 из 4 проверенных подписей, на втором — 4 из 4; идеальная точность не заявляется. Исходники фото и распознанный текст не сохранены в репозитории и не отправлены во внешние сервисы.
- Итоговый полный прогон с включёнными реальными smoke: `231 passed, 10 subtests passed in 6.62s`, без пропусков; `git diff --check` прошёл.
