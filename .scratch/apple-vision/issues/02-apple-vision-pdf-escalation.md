# 02: Apple Vision в PDF-пайплайне и строгой эскалации

Status: completed

**What to build:** Пользователь распознаёт многостраничные сканы через `apple-vision` и включает движок в существующую строгую цепочку повторного распознавания отмеченных страниц. Результаты и отчёты остаются совместимыми с текущими потребителями.

**Blocked by:** 01 — Локальное распознавание изображений через Apple Vision.

## Acceptance criteria

- [x] Многостраничный скан распознаётся через существующие стадии рендеринга PDF и предобработки, с сохранением страниц и соответствия геометрии обработанному изображению.
- [x] Markdown, TXT и JSON сохраняют существующий контракт вывода; CLI-тесты проверяют пользовательские форматы и коды завершения.
- [x] Пригодные текстовые PDF продолжают использовать нативное извлечение текста и таблиц вместо ненужного OCR.
- [x] `apple-vision` принимается как участник цепочки эскалации; все выбранные движки проходят предварительную проверку требований.
- [x] На отмеченных страницах сохраняется заданный порядок попыток, действующие правила выбора результата и сведения о попытках и выбранном источнике.
- [x] Ошибка Apple Vision останавливает строгую цепочку, а не пропускается и не вызывает скрытую замену движка.
- [x] Поведение проверено через публичный интерфейс распознавания и существующие тестовые подходы для OCR, CLI и автоматизации.
- [x] Изменения не добавляют собственное определение поворота по четырём вариантам и не обещают новое восстановление таблиц средствами Apple Vision.

### 2026-11-15 — Реализация и проверка

- Добавлен вызов существующих `render_pages` и `preprocess` перед распознаванием каждой выбранной страницы через Apple Vision. RED: адаптер получил исходный PDF вместо PNG; GREEN после подключения рендеринга.
- Публичный тест создаёт синтетический трёхстраничный raster PDF, реально рендерит страницы 2–3 при 180 DPI и проверяет предобработку `none`/`basic`: 1000×500 / 2000×1000, соответствующие пиксельные прямоугольники. Только внешний PyObjC заменён тестовой реализацией.
- Проверено через `recognize` и CLI: порядок `tesseract → apple-vision → easyocr`, выбор по действующей оценке качества, сведения `decision`, предварительная проверка до baseline и немедленная остановка на ошибке Apple Vision. Действующие правила эскалации менять не понадобилось.
- Проверены Markdown/TXT/JSON и коды ошибок CLI. Реальное нативное извлечение текста и таблицы из синтетического текстового PDF даёт тот же результат при `tesseract` и при `apple-vision` с эскалацией, без необходимости устанавливать OCR-движок.
